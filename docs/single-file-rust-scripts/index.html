🦀 Single-File Rust Scripts

Small Rust programs do not need a Cargo project. A single .rs file can be compiled directly with rustc, which is useful for repository tools, demos, and scripts that only need the standard library.

The basic workflow

Create a file with a normal Rust main function:

fn main() {
    println!("Hello from Rust");
}

Compile it to a native executable, then run that executable:

mkdir -p builds
rustc scripts/test-tui/test.rs -o builds/test
./builds/test

The source file is portable Rust source. The generated binary is platform-specific and should normally be ignored by Git.

Making the source directly executable

This repository uses a shell/Rust polyglot header at the top of scripts/test-tui/test.rs:

#!/bin/sh
//bin/sh -c 'ROOT=$(CDPATH= cd -- "$(dirname -- "$0")/../.." && pwd); BIN="$ROOT/builds/test"; mkdir -p "$ROOT/builds"; [ "$0" -nt "$BIN" ] && rustc "$0" -o "$BIN"; exec "$BIN" "$@"' "$0" "$@"; exit $?

The same lines are valid to both interpreters:

  • The operating system reads the first line and starts /bin/sh.
  • The shell executes the second line, compiles the file when needed, and replaces itself with the binary.
  • rustc recognizes and ignores the first line as a Unix shebang. It reads the second line as a Rust comment, so compilation continues at the Rust code below it.

Build caching: the [ "$0" -nt "$BIN" ] check recompiles only when the source is newer than builds/test. Delete the binary whenever a clean rebuild is needed.

Running this repository's example

Make the script executable once:

chmod +x scripts/test-tui/test.rs

Then launch the Markdown TUI directly or through just:

./scripts/test-tui/test.rs
just test-tui

The example renders headings, lists, emphasis, and inline code using ANSI terminal sequences. Press q or Ctrl-C to exit. When output is redirected instead of attached to a terminal, it prints plain text and exits without waiting for input.

When to use Cargo instead

Direct rustc scripts work best for small, standard-library-only programs. Use Cargo when the program needs:

  • Third-party crates or feature flags
  • Multiple Rust modules or binaries
  • Unit and integration test organization
  • Repeatable dependency resolution with Cargo.lock
  • Portable build configuration across operating systems

For a larger program, start with cargo new and let Cargo manage compilation and dependencies.
